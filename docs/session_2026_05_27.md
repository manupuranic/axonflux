# Session — 27 May 2026

Pamphlet renderer + AI chat overhaul. Continuation of pamphlet DSL work; this session focused on rendering correctness (grid reflow, last-page layout, banner placement) and chat reliability (atomic tools to compensate for weak LLM tool-chaining).

---

## 1. Renderer fixes — A4 grid reflow

### Problem
- Deleted product slots left phantom blanks in 5×5 grid.
- Last page (partial) had a full empty row taking ~20% of A4 height.
- Banners + footer inserted "above the footer" got pushed onto a fresh print page.

### Fix
**`_node_has_content` pre-filter** ([api/tools/pamphlets/render/html.py](api/tools/pamphlets/render/html.py)) — recursively checks slots/products against `items_lookup`; deleted items dropped before chunking. Grid reflows continuously, no per-cell logic.

**Last-page row sizing** — pre-computed `calc((210mm - 32px - (rows-1)*gap_px)/rows)` matches full-page row height exactly. Partial last page uses `grid-auto-rows: {row_height}` + `height:auto`. Cards look pixel-identical across pages; leftover whitespace is <1 row instead of a full empty track.

**Trailing-node injection** — `render_pamphlet` now finds the paginated grid section, splits `page.children` into `leading | grid | trailing`, and passes `trailing_html` to `_render_paginated_grid`. The grid renderer tucks trailing content INSIDE the last `.a4-page` div:
- Partial last page → trailing renders below grid in remaining row space
- Full last page → flex column with `grid:flex 1; min-height:0;` + trailing pinned to bottom

This eliminates the `break-after:page` print bug where last-products page no longer matched `:last-child` (because banner became the new last sibling) and forced trailing content onto its own sheet.

### CSS additions
- `.product-card .product-img-wrap{width:var(--img-w,38%)}` — per-section image width via CSS variable
- `.page-trailing{margin-top:8px;display:flex;flex-direction:column;gap:4px;}`

## 2. Chat reliability — atomic tools

### Root cause
Haiku 4.5 (chat default) reliably calls `get_layout` then bails. Multi-step chains like "find section_id → update_node(section_id, {cols:4})" fail silently — LLM hallucinates "Done!" without round-2 tool call. Symptom: user says "make it 4 cards per row", AI confirms, nothing changes.

### Fix layer 1 — atomic single-call tools
Collapsed common 2-step chains into one tool with auto-discovery:

| Tool | Replaces |
|---|---|
| `set_grid(cols, rows, image_width_pct)` | get_layout → update_node on the grid section |
| `style_region(region, font_size_px, ...)` | get_layout → N × update_node across footer/header/text nodes |
| `add_banner(headline, position, ...)` | get_layout → edit_layout(insert) |

`region` resolver (`_find_region_nodes`) handles `footer | header | all_text | all_headings`. Footer detection prefers `contact_strip` node, falls back to "last child of page" for text-based footers.

### Fix layer 2 — universal `apply_dsl_patch(ops)`
One tool covers all DSL mutations. Op vocabulary mirrors JSON Patch but uses node IDs (LLM-friendly) instead of pointers:

```json
[
  {"op":"set",    "node_id":"abc", "field":"cols", "value":4},
  {"op":"style",  "node_id":"abc", "style":{"font_size_px":18}},
  {"op":"insert", "parent_id":"page1", "index":0, "node":{...}},
  {"op":"remove", "node_id":"xyz"},
  {"op":"move",   "node_id":"xyz", "new_parent_id":"page1", "index":5}
]
```

Per-op results returned individually — partial success doesn't kill the batch.

### Fix layer 3 — DSL summary in system prompt
`build_system_prompt(title, count, dsl=...)` now injects a compact tree outline showing node IDs + key fields. LLM reads IDs from the prompt → emits `apply_dsl_patch(ops)` directly with NO `get_layout` round-trip. Sections with many product children get collapsed (first 2 + "... N more" + last 1) to keep token cost down.

### Lenient ops parsing
Haiku occasionally emits `ops` as a JSON string with Python-literal syntax (`{op:"set",...}` instead of `{"op":"set",...}`). `_coerce_ops_list` tries `json.loads`, then a regex repair (quote bare keys, single→double quotes), then a clear error with a hint. No more `'str' object has no attribute 'get'` crashes.

## 4. Architecture takeaways

### Pattern: atomic tools over composable primitives (for weak LLMs)
The 18→6 tool consolidation done on 2026-05-25 was correct for context efficiency, but assumed Sonnet-grade tool-chaining. Haiku breaks this assumption. New rule: every common semantic operation should be expressible in ONE tool call. The taxonomy emerging:
- `set_*` for layout/config (no get_layout needed)
- `style_*` for visual properties (semantic regions auto-resolved)
- `add_*` for inserts (no parent_id discovery)
- `apply_dsl_patch` as the universal escape hatch

### Pattern: state in system prompt for stateful UIs
Instead of forcing the LLM to call `get_layout` every turn to discover IDs, the DSL summary lives in the system prompt for the lifetime of the chat session. Trade-off: ~500 extra tokens per turn for a single round-trip eliminated. Net win because the round-trip was the failure point.

### Pattern: defensive parsing at LLM boundaries
LLMs are an external system. Treat their outputs like untrusted input: validate, normalize, repair, then process. `_coerce_ops_list` is the template for this — try strict parse, try lenient parse, return informative error.
